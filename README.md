# Portfolio

소프트웨어 엔지니어의 경력과 프로젝트를 장기적으로 관리하는 정적 포트폴리오 사이트입니다.

## 프로젝트 구조

```text
portfolio/
├── AGENTS.md                # 작업 절차, 콘텐츠 작성/사실 검증/코드 및 디자인 원칙
├── README.md                # 프로젝트 개요 및 실행 방법
├── docs/
│   ├── CONTENT_MODEL.md     # 콘텐츠 스키마 및 유형 정의
│   ├── SOURCE_OF_TRUTH.md   # 자료 우선순위 및 출처 관리
│   ├── CLAIM_AUDIT.md       # 핵심 주장 검토 및 검증 가이드
│   └── VISUAL_SPEC.md       # 디자인 시스템, 컴포넌트 및 다이어그램 규칙
├── src/
│   ├── content/             # 마크다운/YAML 콘텐츠 데이터
│   │   ├── experience/      # 회사 또는 조직 경력
│   │   ├── projects/        # 프로젝트 (개인/팀)
│   │   └── articles/        # 기술 글 및 회고
│   ├── components/          # 공통 및 프리미엄 UI 컴포넌트
│   ├── layouts/             # 레이아웃 템플릿
│   └── pages/               # 라우팅 페이지
└── public/                  # 정적 자산
    ├── diagrams/            # 시스템 아키텍처 및 흐름 다이어그램
    ├── screenshots/         # 프로젝트 스크린샷
    └── documents/           # PDF 이력서 및 기타 증빙 서류
```

## 핵심 원칙

이 포트폴리오는 **AGENTS.md**에 기술된 규칙을 최우선으로 따릅니다.
1. **사실에 기반한 서술 (Factuality)**: 수치와 성과는 명확한 측정 환경과 근거를 함께 제시합니다.
2. **역할과 기여의 명확한 구분**: 개인의 기여와 팀의 기여를 명확히 구분하여 작성합니다.
3. **지속 가능한 아키텍처**: 새로운 콘텐츠 추가 시 기존 페이지의 회귀(Regression) 없이 자동으로 목록과 상세에 반영됩니다.
4. **웹과 PDF 지원**: 화면으로 보는 웹 인터페이스와 인쇄용 PDF 출력물에서 동일한 신뢰성과 최상의 레이아웃을 보장합니다.
