# 이력서 시장 검토 기록

## 2026-08-25

### 검토 대상

- 3–5년차 및 3–7년차 Java·Spring 백엔드 채용 공고
- 2025–2026년 공개 개발자 PDF 이력서의 첫 화면과 경력 서술 순서
- ATS의 DOCX 파싱 실패 요인

### 반영한 결정

- Java/Kotlin·Spring 경력을 첫 메시지로 사용한다.
- AI 경험은 기존 백엔드 경험의 확장으로만 배치한다.
- 상단에는 이름·연락처와 2~3줄 경력 요약을 두고, 직무·경력 기간·학력은 각 섹션에서 파싱 가능한 텍스트로 유지한다.
- 상세 경력은 면접 질문으로 이어질 사례 제목과 문제, 판단, 직접 구현, 검증·결과와 책임 한계를 설명한다.
- 프로젝트는 모든 회사 경력 뒤에 KExcel과 WorkShield만 짧게 배치한다.
- 지투이는 첫 경력이자 현재 핵심 메시지와 거리가 있어 키오스크와 포탈 권한 구현 범위만 짧게 남긴다.
- 수동 페이지 나누기는 사용하지 않고 회사별 대표 사례 최대 두 개와 프로젝트별 구조화 필드로 분량을 통제하며, 페이지 수보다 첨부본 수준의 글자 크기와 행간을 우선한다.
- 본문은 첨부 이력서의 단일 열, 회사 아이콘 열과 프로젝트 본문 들여쓰기를 따른다. PDF·DOCX의 정렬축을 맞추기 위한 단순한 고정 폭 표만 허용하고, 사진·중첩 표·다단·텍스트박스는 사용하지 않는다.

### 2026-08-26 첨부 이력서 형식 반영

- `이름 → 연락처 → 경력 요약 → 경력 → 학력 → 스킬 → 수상·자격 → 링크` 순서를 템플릿의 기준으로 삼았다.
- 현재 확인된 KExcel과 WorkShield는 회사 경력 뒤에 같은 프로젝트 블록 형식으로 유지했다.
- 상단에는 `Professional Summary`와 근거 3개를 배치해 운영 실패 경계, 개발 리드·AWS 경험과 개인 프로젝트의 측정 결과를 먼저 확인할 수 있게 했다.
- 프로젝트 블록은 `제목·기간·배경·역할·주요 성과·핵심 구현·기술스택·한계`로 통일했다.
- 회사 경력의 미확인 성능·장애·트래픽 수치는 추가하지 않고, 측정 환경이 연결된 프로젝트 수치만 유지했다.
