# 서술 규칙 및 가이드라인 (Writing Rules)

## 1. 공통 서술 규칙

### 사용하기 좋은 관점

- 실패 시나리오
- 재실행과 중복 처리
- 상태 분리
- 데이터베이스 최종 제약
- 모듈 간 데이터 계약
- 측정 환경을 포함한 성능 검증
- AI와 결정론적 서버의 책임 분리
- 실제 실행 trace
- 채택·보류·폐기 판단
- 한계와 책임 범위

### 금지 또는 고위험 표현

근거 없이 사용하지 않는다.

- 대규모 트래픽
- 실시간 트래픽
- 무중단
- 고가용성
- 완벽한 멱등성
- 자동 복구
- 장애율 감소
- 실패율 0%
- 메모리 사용량 99.8% 감소
- 성능 518% 개선
- 법률 정확도
- 개인정보 암호화
- AI 기반 자동 판정
- 혼자 전체 설계
- 운영 비용 절감
- 유지보수 비용 대폭 절감

### 권장 대체 표현

- 자동 복구
  - 특정 상태의 미완료 작업 재처리
- Thread Safe
  - 동시 쓰기 감지 및 Fail-Fast
- 메모리 99.8% 절감
  - DSL 추가 할당량을 약 200KB에서 364B로 축소
- 성능 518% 개선
  - 병합 처리량을 3.36에서 17.42 ops/s로 개선
- 내생성 해결
  - 상호 의존성을 고려한 2-Stage 구조
- 법률 검토 자동화
  - 표준 대비 검토 후보와 근거 제공
- 결제 유실 복구
  - 승인 후 재화 제공 미완료 주문 재처리

## 2. 미확인 및 추후 확인 항목

현재 포트폴리오 작성을 막는 치명적인 미확인 정보는 없다.

선택적으로 확인할 항목:

- 결제 복구 반복문 문제의 당시 수정 여부
- 각 회사 업무의 정확한 사용자 규모와 운영량
- 공개 가능한 화면 또는 재구성 이미지
- WorkShield 회고 URL
- 영화 프로젝트 저장소 최종 URL
- 전기차 프로젝트의 공식 PM 역할 여부

확인되지 않은 항목은 문서에서 제외하거나 제한된 표현을 사용한다.

## 3. 갱신 규칙

다음 경우 사실 원본 문서를 갱신한다.

- 사용자가 기존 사실을 수정하거나 추가 확인함
- 저장소 코드와 README가 변경됨
- 새로운 벤치마크가 추가됨
- 공개 범위가 변경됨
- 프로젝트 상태가 변경됨
- 새 경력 또는 프로젝트가 추가됨
- Claim Audit에서 위험 표현이 발견됨

갱신 시 변경된 사실과 영향을 받는 콘텐츠 slug를 함께 기록한다.
